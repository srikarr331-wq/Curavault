# CuraVault Development Agents\n\nThis document describes the AI agents and development guidelines for CuraVault.\n\n## Backend Development Agent\n\n**Responsibilities:**\n- Implement FastAPI endpoints\n- Create database models and migrations\n- Build business logic services\n- Implement authentication and authorization\n- Handle file uploads and storage\n- Create API tests\n\n**Guidelines:**\n- Follow PEP 8 code style\n- Write comprehensive docstrings\n- Create unit tests for all functions\n- Validate input with Pydantic schemas\n- Use type hints throughout\n\n**Key Files:**\n- `backend/app/api/routes/` - API endpoints\n- `backend/app/models/` - Database models\n- `backend/app/services/` - Business logic\n- `backend/app/security/` - Auth & encryption\n- `backend/tests/` - Test suite\n\n---\n\n## Frontend Development Agent\n\n**Responsibilities:**\n- Build React components\n- Implement page layouts\n- Create API service clients\n- Manage application state with Zustand\n- Implement authentication flows\n- Create component tests\n\n**Guidelines:**\n- Use functional components with hooks\n- Write prop types properly\n- Follow React best practices\n- Create reusable components\n- Test user interactions\n\n**Key Files:**\n- `frontend/src/components/` - Reusable components\n- `frontend/src/pages/` - Page layouts\n- `frontend/src/services/` - API clients\n- `frontend/src/store/` - State management\n- `frontend/src/types/` - TypeScript types\n\n---\n\n## DevOps Agent\n\n**Responsibilities:**\n- Docker image management\n- CI/CD pipeline configuration\n- Infrastructure setup and monitoring\n- Database migrations\n- Deployment and scaling\n\n**Guidelines:**\n- Use multi-stage Docker builds\n- Implement health checks\n- Configure environment variables\n- Document deployment steps\n- Monitor application performance\n\n**Key Files:**\n- `backend/Dockerfile` - Backend image\n- `frontend/Dockerfile` - Frontend image\n- `docker-compose.yml` - Local development\n- `.github/workflows/` - CI/CD pipelines\n- `docs/DEPLOYMENT.md` - Deployment guide\n\n---\n\n## Security Agent\n\n**Responsibilities:**\n- Implement authentication and authorization\n- Encryption and data protection\n- Input validation and sanitization\n- Security testing\n- Vulnerability scanning\n- Audit logging\n\n**Guidelines:**\n- Follow OWASP guidelines\n- Use secure libraries\n- Implement rate limiting\n- Use HTTPS/TLS\n- Regular security audits\n- Keep dependencies updated\n\n**Key Files:**\n- `backend/app/security/` - Security modules\n- `docs/SECURITY.md` - Security guide\n- `.github/workflows/security.yml` - Security scanning\n\n---\n\n## QA Agent\n\n**Responsibilities:**\n- Write comprehensive tests\n- Test coverage maintenance\n- Manual testing procedures\n- Bug verification\n- Performance testing\n\n**Guidelines:**\n- Aim for 80%+ code coverage\n- Test happy path and error cases\n- Write clear test names\n- Document test scenarios\n- Automate repetitive tests\n\n**Key Files:**\n- `backend/tests/` - Backend tests\n- `frontend/src/__tests__/` - Frontend tests\n- `backend/tests/sample_data.py` - Test fixtures\n\n---\n\n## Documentation Agent\n\n**Responsibilities:**\n- API documentation\n- User guides\n- Developer documentation\n- Architecture documentation\n- Deployment guides\n\n**Guidelines:**\n- Keep documentation up-to-date\n- Include code examples\n- Use clear language\n- Add diagrams where helpful\n- Version documentation\n\n**Key Files:**\n- `README.md` - Project overview\n- `docs/API.md` - API documentation\n- `docs/DATABASE.md` - Database schema\n- `docs/SECURITY.md` - Security implementation\n- `docs/DEPLOYMENT.md` - Deployment guide\n- `USER_MANUAL.md` - User guide\n\n---\n\n## Workflow\n\n### Feature Development\n\n1. **Planning**: Create issue with requirements\n2. **Design**: Document architecture if complex\n3. **Implementation**: Write code with tests\n4. **Review**: Code review by team\n5. **Testing**: QA tests the feature\n6. **Deployment**: Merge and deploy to production\n\n### Bug Fixing\n\n1. **Report**: Create bug issue with reproduction steps\n2. **Triage**: Assign severity and priority\n3. **Fix**: Implement fix with test\n4. **Verify**: QA confirms fix\n5. **Release**: Deploy fix to production\n\n### Release Process\n\n1. **Prepare**: Finalize features for release\n2. **Test**: Comprehensive testing\n3. **Document**: Update changelog and docs\n4. **Release**: Tag and deploy\n5. **Announce**: Notify users of release\n\n---\n\n## Code Quality Standards\n\n### Backend (Python)\n- PEP 8 compliant\n- Type hints required\n- Docstrings for public functions\n- Minimum 80% test coverage\n- No hardcoded secrets\n- Async/await for I/O operations\n\n### Frontend (TypeScript/React)\n- ESLint compliant\n- Proper TypeScript typing\n- Functional components with hooks\n- Component prop documentation\n- Minimum 80% test coverage\n- CSS modules or Tailwind classes\n\n---\n\n## Testing Strategy\n\n### Backend Tests\n```bash\n# Unit tests\npytest backend/tests/test_api.py\n\n# With coverage\npytest --cov=app backend/tests/\n\n# Integration tests\npytest backend/tests/test_integration.py\n```\n\n### Frontend Tests\n```bash\n# Component tests\nnpm run test\n\n# E2E tests\nnpm run test:e2e\n\n# With coverage\nnpm run test -- --coverage\n```\n\n---\n\n## Performance Targets\n\n- **API Response Time**: < 200ms (p95)\n- **Page Load Time**: < 3s\n- **Test Coverage**: > 80%\n- **Code Quality**: A grade on SonarQube\n- **Security**: Zero critical vulnerabilities\n- **Database Query Time**: < 100ms (p95)\n\n---\n\n## Communication\n\n- **Issues**: Use GitHub Issues for tracking\n- **PRs**: Use Pull Requests for code review\n- **Discussions**: Use GitHub Discussions for brainstorming\n- **Chat**: Slack for real-time communication\n\n---\n\n## Dependencies\n\n###
